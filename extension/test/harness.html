SentinelAI — Extension Test Harness

Type or paste into the fields below. A warning panel should appear at the bottom-right. Nothing on this page talks to the backend — the extension does all of it.

Before you start

  1. Backend running: uvicorn app.main:app --port 8000
  2. Extension loaded at chrome://extensions → Developer mode → Load unpacked → pick the extension/ folder
  3. This page opened over http://localhost:8080, not file://

Sample values

All fabricated. The Aadhaar and card numbers are checksum-valid but not issued to anyone — never test with a real one.

Click a chip to copy it, then paste into a field below.

4 — Password field (control)

Must stay silent. Its value is never read, never scanned, never sent. Paste a card number in here and nothing should happen at all.

5 — QR codes

Right-click any code below and choose “Check this QR code with SentinelAI”. A panel appears at the bottom-right showing where the code actually goes before the verdict — that line is the point of the feature, because a QR code is unreadable to a human being.

Every payload is fabricated. The payment addresses are syntactically valid and belong to nobody. Regenerate them with python extension/test/generate_qr_samples.py.

6 — Clipboard Guardian

Copy one of the fake credentials below, then paste it into the field underneath. The paste is held — not silently blocked — and a panel offers Paste masked · Cancel paste · Paste anyway. None of these are real keys; they are shaped correctly and belong to nobody.

Paste target

The destination line fills in a moment after the panel appears. On this page it will say SentinelAI does not recognise localhost:8080… unless you are on localhost, which the table classifies as a development server — which is the point: where you paste changes the answer.

7 — Chat scam detection

Each block below is a scam script written the way it actually arrives. Select one, right-click it, and choose "Check this message with SentinelAI". No adapter, no MutationObserver, and no chat app is involved — this is the path that works on every site, and the path that still works when WhatsApp changes its markup.

These are fabricated. The phone numbers, UPI IDs and amounts belong to nobody, and nothing here is sent anywhere until you right-click.

Automatic watching is a separate thing and is off. It only runs on WhatsApp Web and Telegram Web, only after you switch it on in the popup, and it shows a marker in the corner the whole time it is running.

8 — Screenshots

Every image below is drawn by this page on a <canvas> as it loads. There is no photograph of a real document anywhere in this repository and there never will be — a project whose entire argument is that pictures of identity documents are dangerous to leave lying around cannot ship one as a test fixture.

Press Attach under a card. It is placed into the file field at the bottom of this section exactly as if you had picked it off your disk, and the extension's upload watcher takes it from there. Save writes the same PNG to your downloads folder, which is how you feed it to the dashboard's screenshot panel.

Upload field

A real file picker works here too — the extension does not know or care that a button on this page put the file in the field. Reading takes a few seconds the first time, while the recogniser loads; after that it is warm. Nothing is uploaded anywhere: this page has no server side, and the image itself never leaves your machine in any case.

What to verify

  • Warning appears within about a second of typing, bottom-right
  • Panel shows a reason and a confidence — never a bare verdict
  • Mask it replaces the value in place, and the panel closes
  • In field 3, the bold Priya and italic Ravi survive masking
  • Field 4 never produces a warning
  • Always allow here silences that one type on this origin, and the popup lists it as reversible
  • Stop the backend, type again → an "offline" note appears rather than silence

QR codes

  • Right-clicking an image offers Check this QR code with SentinelAI; right-clicking plain text does not
  • A spinner appears immediately, then is replaced by the result — the click never appears to do nothing
  • The destination line sits above the verdict, in the largest type on the panel
  • The ₹50,000 code says it pays out, not that it receives
  • The ₹45 tea-stall code is safe — if that one alarms, the feature is unusable in India
  • Right-click a photo that has no QR code in it → "No QR code found", not a green panel
  • Stop the backend, right-click again → "could not reach its backend", never a verdict

Clipboard

  • Pasting an AKIA… key does not put text in the field until you choose — the panel appears first
  • The block is instant. There is no perceptible delay, because no network call has happened yet
  • Cancel paste leaves the field exactly as it was, with the caret still in it
  • Paste masked inserts AKIA••••••••••••••••, and Ctrl+Z still works
  • Paste anyway inserts the original and does not then show a second warning for the same value
  • Pasting ordinary prose is untouched — no panel, no delay, nothing
  • Stop the backend and paste a key → the panel still appears (it is local), and the destination line reads "could not check where this was going"
  • Paste into field 4 (password) → nothing at all. The clipboard is never even read

Chat scams

  • The menu item appears only when text is selected — right-click with nothing highlighted and it is absent
  • The OTP script is dangerous, and the panel names the pattern: "This resembles a common OTP fraud"
  • The panel quotes the line that triggered it, and that quote appears character-for-character in the block above
  • The friendly UPI message is not an alarm — a person sharing their payment ID is ordinary, and flagging it makes the tool unusable in India
  • Select two words and check → "select more of the conversation", not a green verdict
  • Stop the backend, then check the OTP script again → it is still dangerous. Tier 1 runs offline, and the footnote reads "pattern checks only"
  • Nothing you check here appears on the dashboard afterwards — the endpoint stores nothing, by design

Screenshots

  • Attaching the Aadhaar card shows a “Checking…” panel first — the read takes seconds and a silent wait is indistinguishable from a broken feature
  • The panel quotes a masked value (XXXX XXXX 9014) and never the number itself
  • The misread card is found too, is labelled a corrected read, and its confidence is visibly lower than the clean card's — that gap is the honesty of the whole module
  • Its reason names the characters that were changed, so you can check the correction against the card yourself
  • Remove from upload genuinely empties the field — check it, do not trust the panel's word for it
  • Upload anyway leaves the file in place and does not warn a second time
  • The delivery note produces nothing at all. A 16-digit order number and a delivery date are not a card number and a date of birth, and a tool that cannot tell the difference is one people switch off
  • Attach a non-image (rename anything to .pdf) → nothing happens, not a "could not check" panel. It was never in scope
  • Stop the backend and attach again → "could not reach its backend". The reading still happened locally; it is the classification that could not
  • Every finding here appears in the dashboard timeline as “found in an image on”, not "caught on" — how it nearly left you is part of the story
  • Save a card, then drop the file on the dashboard's screenshot panel → the same finding, from the same code, with no extension installed at all
